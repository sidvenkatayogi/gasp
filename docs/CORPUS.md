# Constructing the shared recoverability corpus

## What the paper specifies

[Section 4.2](https://arxiv.org/html/2602.00173v1#S4.SS2) describes GSM8K
clean-solved selection: generate four clean solutions at temperature .7 and retain
a question only when all four final answers are correct. Sample a correct solution,
cut its reasoning at alpha in {0, .25, .5, .75}, and replace the subsequent window
with a locally coherent corruption generated by a held-out GPT-5 polluter. Evaluate
the tested agent's final answer under that corrupted prefix.

[Appendix B](https://arxiv.org/html/2602.00173v1#A2) supplies the polluter prompt:
edit the supplied short continuation in place, preserve its style, and introduce
an objectively incorrect mathematical statement. This implementation reuses that
template from `src/gasp/prompts.py`. The ~10%-of-trace window follows Section 3.2.

These details support constructing our own corpus. They do not specify every
choice needed to regenerate the authors' exact examples. In particular, the paper
does not give an exact GPT-5 snapshot or decoding configuration, clearly establish
a single fixed initial-checkpoint subset for all tested policies, or resolve how
to handle invalid generated corruptions. Using the Appendix B training-polluter
template for the held-out generator is our explicit interpretation.

## Choices for our paired experiment

The user requested **GPT-6.1 Sol** for corruption generation. This replaces the
paper's GPT-5 evaluator and is a declared evaluation deviation. It does not change
the trainable agent/polluter or their self-generated repair guidance. Both unified
and split use the exact same completed corpus.

| Choice | Recorded setting |
|---|---|
| Selection model | Resolved initial DeepSeek checkpoint, before either condition trains |
| Selection | K=4, T=.7, all correct; evaluation seed 10001; same verifier and sampling settings as the resolved config |
| Clean trace | One fresh correct, nonempty trace per retained question; at most 32 attempts by default; failure stops preparation |
| Prefix positions | All four alphas per retained question, sharing its sampled trace; equal weight per context |
| Window | `min(128, max(1, floor(.1 * trace_tokens)))`, starting at `floor(alpha * trace_tokens)` |
| Generator | `gpt-6.1-sol`, Responses API, Appendix B polluter prompt and system message; no gold answer sent |
| API settings | Reasoning effort `low`, maximum 4096 output tokens including reasoning, `store=false`; temperature/top-p omitted |
| Response handling | One request per context; require completed status, matching model, nonempty tagged output, and a changed window; no automatic retries or replacement rows |
| Corpus scope | Fixed initial clean-solved questions only; no claim of full GSM8K coverage |

The generator ID and supported effort values are documented on the
[official model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
It exposes `gpt-6.1-sol`, not a dated snapshot. The provenance records that limitation;
each saved response retains the returned model identifier, provider timestamp/usage
when supplied, and local receipt time. Freezing the actual output bytes gives both
conditions the same test even if later calls to that identifier change.

Structural validation cannot establish that every edit is mathematically wrong
and locally coherent. Inspect the clean/polluted pairs before using the corpus and
record that inspection alongside it. The generator labels semantic review as not
performed. Do not silently hand-edit failed examples, delete response files to
resample until desirable, or tune generation using either trained agent's scores.
Any revised construction policy needs a separately documented corpus version.

## Commands

First run the download and training-data preparation commands in the README. They
produce `data/raw/gsm_raw.jsonl` and the shared `resolved_config.json`.

On the GPU environment, create clean test contexts:

```bash
python -m gasp prepare-eval-contexts --config data/full-v4/resolved_config.json \
  --source data/raw/gsm_raw.jsonl --output data/full-v4/eval-contexts.jsonl
```

This writes a hashed context cache and a `.audit.jsonl` file containing filter
outputs, rejected/accepted clean samples, and selection decisions. It does not
substitute GSM8K reference solutions. The full profile samples four solutions
for each of four questions together (16 sequences). A `.progress.pt` checkpoint
commits each completed batch, retaining selected contexts, sampling RNG, counts and audit
position. Use `--resume` with the same source/config/code/runtime to continue a
trusted checkpoint; interrupted audit tails are preserved separately. Inspect
errors before resuming a failed batch. `--max-seconds N` stops at a batch
boundary without publishing a partial corpus. `--questions N` limits the first N
candidate questions for a separate preparation pilot; omit it for the full corpus.

Set `OPENAI_API_KEY` in the execution environment. The next stage can run on CPU
and makes paid API calls. Start with a bounded batch:

```bash
python -m gasp generate-eval --source data/full-v4/eval-contexts.jsonl \
  --output data/full-v4/held-out-corruptions.jsonl --max-requests 4
```

Inspect the saved responses, then repeat the same command without `--max-requests`
to finish. There are four requests per selected question. The limit counts new
requests in that invocation; already saved responses are reused. A partial run
reports `complete: false` and does not publish a final corpus. Request settings
and the input hash must match when resuming. API credentials are never saved.

The `.responses/` directory stores exact requests and responses before parsing,
including invalid responses. A malformed, incomplete, unchanged, or mismatched-model
response stops the run for investigation. It is not automatically rebilled on
resume. A transport failure before a response is saved cannot be recovered from
the local cache; a later retry might incur another API charge.

Once generation completes and the examples have been inspected, import them:

```bash
python -m gasp import-eval --config data/full-v4/resolved_config.json \
  --source data/full-v4/held-out-corruptions.jsonl \
  --provenance data/full-v4/held-out-corruptions.jsonl.provenance.json \
  --output data/full-v4/eval.jsonl
```

The importer verifies the generated corpus hash and builds shared prompt tokens.
Both training conditions then use `data/full-v4/eval.jsonl`. Existing externally
supplied GPT-5 corpora remain importable with their actual provenance; new generation
uses only the user-selected Sol model. As of 2026-10-17 UTC, the source datasets
are validated, the model revision is pinned, and DeepSeek context preparation is
being relaunched with four-question batches on Colab. One live GPT-6.1 Sol response from an already-committed context
passed format, semantic and prompt-length checks; it is preserved as a serial-v3 preflight artifact. New batched-v4 traces receive
their own responses; old responses are not mixed into that corpus. The key stays
on the Mac. The completed corruption corpus is still pending.
